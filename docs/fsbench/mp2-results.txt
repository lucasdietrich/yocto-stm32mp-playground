Metrics:
  Bandwidth : higher is better  (seq scan, checkpoint)
  IOPS      : higher is better  (WAL = approx max TPS; index = lookup throughput)
  Avg lat   : lower is better   (commit round-trip time)
  p99 lat   : lower is better   (tail latency seen by slow clients)

PostgreSQL tuning notes:
  WAL fsync IOPS < 200  --> storage is your TPS bottleneck
  WAL group >> WAL fsync --> synchronous_commit=off would help greatly
  btrfs nodatacow used  --> avoids COW write amplification on heap files
  dm-crypt overhead     --> run 'cryptsetup benchmark' to check AES-NI/CE
